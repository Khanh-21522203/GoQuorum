01

Decision

Use a small first-party gossip component because membership semantics are part of GoQuorum's domain model.

Recommendation: implement only the feature set GoQuorum already needs: local state table, periodic peer fanout, push-pull exchange, deterministic merge, failure-detector hooks, and membership-manager updates. Do not adopt a generic gossip package unless the project later needs large-cluster behavior, advanced suspicion, encryption, or WAN-aware membership.
02

Scope

This plan is intentionally narrow. Heartbeats still detect liveness; gossip only spreads that knowledge.

In scope

  • Known static peers from YAML config.
  • Node status propagation: joining, active, suspect, failed, leaving.
  • Versioned state entries with deterministic merge.
  • Fanout-based periodic exchange over /internal/gossip/exchange.
  • Failure detector callbacks into gossip.
  • Focused unit and integration tests for convergence.

Out of scope

  • Replacing heartbeat failure detection.
  • Full SWIM probe/suspicion protocol.
  • Dynamic node discovery outside current join/leave paths.
  • Encrypted gossip payloads beyond existing TLS/mTLS transport.
  • WAN gossip, seed nodes, or cross-region tuning.
  • Persistent gossip log storage.
03

Before vs. Plan

The current implementation is already small and first-party. The plan mainly clarifies responsibilities, merge ordering, and test seams rather than changing the runtime surface.

Current implementation

  • Gossip owns state, scheduling, peer picking, HTTP transport, and merge behavior in one type.
  • Merge is effectively wall-clock last-write-wins using UpdatedAt.
  • HTTP exchange is embedded directly in the gossip component, which makes merge behavior harder to test in isolation.
  • The public shape is simple and works with existing /internal/gossip/exchange.

Planned implementation

  • Gossip becomes the lifecycle coordinator and facade over smaller collaborators.
  • GossipState owns deterministic merge: version/incarnation first, timestamp second, stable tie-break last.
  • GossipTransport, PeerPicker, and MembershipSink become replaceable seams for tests.
  • The external wiring stays nearly the same: same config shape, same route, same failure-detector callbacks.

05

OOP Architecture

Keep the design object-oriented around small collaborators. The core state logic should be testable without HTTP or goroutines.

aggregate root

Gossip

Owns lifecycle: start loop, stop loop, run rounds, expose public methods used by main.go and InternalAPI.

state object

GossipState

Owns map[NodeID]NodeEntry, merge rules, self-entry protection, snapshots, and deterministic stale-entry rejection.

value object

NodeEntry

Immutable-style membership fact: node ID, HTTP address, status, incarnation/version, update timestamp, and source node.

port/interface

GossipTransport

Interface for push-pull exchange. HTTP JSON is one adapter; tests can use an in-memory fake.

policy

PeerPicker

Pure fanout selection from known peers. It should bound fanout, skip self, and be deterministic under injected RNG in tests.

adapter

MembershipSink

Thin interface over MembershipManager.UpdatePeerStatus. This prevents gossip tests from requiring full cluster config.

Suggested shape: Gossip coordinates; GossipState decides; GossipTransport talks; MembershipSink publishes the result. That keeps domain logic out of HTTP handlers.
06

Implementation Steps

The order keeps behavior testable at each step and avoids replacing too much at once.

Define the gossip contract

Create explicit request/response DTOs and entry semantics: node ID, HTTP address, status, incarnation/version, updated timestamp, and source node. Keep JSON transport for compatibility with the existing internal route.

internal/cluster/gossip.gointernal/server/internal_api.go

Make merge deterministic

Prefer version/incarnation first, timestamp second, and stable node ID tie-break last. Avoid wall-clock-only last-write-wins because clock skew can resurrect stale states.

Merge()unit tests

Separate state mutation from transport

Keep a small state store API: SetSelf, MarkPeer, Merge, Snapshot. Put HTTP exchange and fanout scheduling around that core, not inside it.

testable coreno network in merge tests

Wire failure detector callbacks

On confirmed failure, gossip FAILED. On recovery heartbeat, gossip ACTIVE and trigger anti-entropy as today. Do not let gossip itself decide liveness.

Replace the current implementation behind the same interface

Keep constructor and server wiring stable where possible: NewGossip, Start, Stop, GetState, Merge. This limits blast radius in cmd/quorum/main.go and server.go.

Add convergence tests

Test that A marks C failed, A gossips to B, B updates membership, C later recovers, and all nodes converge to active after exchange. Add stale update tests so older gossip cannot overwrite newer state.

08

Done Criteria

The rewrite is complete when these are true.

Behavior

  • Peers converge on active/suspect/failed/leaving state through gossip exchange.
  • Stale gossip entries cannot overwrite newer local state.
  • Failure and recovery callbacks preserve anti-entropy behavior.
  • Disabling gossip in config stops the spread loop and route wiring remains safe.

Verification

  • Unit tests cover merge ordering and self-entry protection.
  • Unit tests cover peer fanout selection bounds.
  • Integration test covers three-node convergence after failure/recovery.
  • go test ./internal/cluster ./internal/server passes.
